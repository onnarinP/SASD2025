# Speculative Generality

## a) ความหมายของ Speculative Generality

**Speculative Generality** เป็น code smell ประเภทหนึ่งที่เกิดจากการออกแบบหรือเขียนโค้ด “เผื่อการใช้งานในอนาคต” มากเกินความจำเป็น  
เช่น การสร้าง abstract class, interface, parameter หรือ extension point ที่ยังไม่มีความจำเป็นในปัจจุบัน
การเขียนโค้ดลักษณะนี้ทำให้ระบบมีความซับซ้อนโดยไม่ก่อให้เกิดประโยชน์จริง ส่งผลให้โค้ดอ่านยาก ดูแลรักษายาก และเพิ่มภาระในการพัฒนา

---

## b) ตัวอย่างโค้ดที่เกิด Speculative Generality

```java
// Interface ที่ถูกสร้างเผื่อไว้
public interface PaymentProcessor {
    void process(double amount);
}

// มี implementation เพียงตัวเดียว
public class CreditCardPayment implements PaymentProcessor {
    @Override
    public void process(double amount) {
        System.out.println("Paying " + amount + " by credit card");
    }
}
```
#### ปัญหา
- มีการใช้งานเพียงรูปแบบเดียว
- ยังไม่มี requirement รองรับ payment แบบอื่น
- การสร้าง interface ทำให้โค้ดซับซ้อนขึ้นโดยไม่จำเป็น

## c) ตัวอย่างโค้ดหลัง Refactoring
```
public class CreditCardPayment {
    public void process(double amount) {
        System.out.println("Paying " + amount + " by credit card");
    }
}
```
#### ผลลัพธ์หลัง refactoring
- ลด abstraction ที่ไม่จำเป็น
- โค้ดเรียบง่าย อ่านเข้าใจง่าย
- สามารถ refactor เพิ่ม abstraction ภายหลังได้ หากมี requirement ใหม่

---

## d) กรณีที่ Speculative Generality ไม่ได้บ่งบอกว่าโค้ดมีปัญหา (กรณีที่ไม่จำเป็นต้อง refactoring)
Speculative Generality อาจไม่ถือเป็นปัญหาในกรณีต่อไปนี้ เช่น
1. มี requirement ชัดเจนในอนาคตอันใกล้ ว่าจะต้องรองรับการขยายระบบ
2. โค้ดเป็นส่วนหนึ่งของ framework หรือ library ที่ต้องรองรับการใช้งานหลากหลายรูปแบบ
3. Abstraction ถูกใช้งานจริงในหลายส่วนของระบบ เช่น เพื่อรองรับ Dependency Injection , Unit Testing
4. การเตรียมโครงสร้างล่วงหน้าช่วย ลดต้นทุนการแก้ไขระบบขนาดใหญ่ในอนาคต
